# StudyOS 产品需求文档

**英文副标题：** Personal Learning & Research Workspace  
**产品形态：** 个人单用户学习与科研管理 SPA  
**目标地址：** `https://USERNAME.github.io/studyos/`

## 1. 产品目标

StudyOS 帮助个人持续管理 Java 后端、AI / Python 与科研论文三类工作。它记录真实学习活动、计划与复盘，并让统计从这些记录推导出来。产品必须可从电脑和手机浏览器使用，GitHub Pages 负责托管静态前端，Supabase Auth 与 PostgreSQL 负责身份和云端持久化。

### 成功标准

- 登录后可创建、查询、更新、删除任务、项目、里程碑和活动记录。
- 统计只来自 Supabase 中当前用户的记录；任务完成不增加学习时长。
- 退出登录或会话失效后，受保护页面与缓存数据不可见。
- RLS 在数据库层阻止匿名访问及跨用户读写。
- 手机 360px、390px、430px 宽度可完成主要工作，无水平溢出。
- `npm run build`、`npm run typecheck`、核心 Vitest 与 Playwright 检查通过。
- GitHub Actions 可用 `npm ci` 构建并部署到 Pages；未配置云端账户时不得宣称已部署。

## 2. 用户与权限

当前版本仅供项目所有者个人使用。登录采用 Supabase 邮箱密码认证；网站不含注册流程。账户通过 Supabase Dashboard 由所有者创建或邀请。忘记密码经 Supabase 邮件恢复；用户可在站内设置新密码。公开的 Supabase Publishable Key 只用于浏览器客户端，授权边界由 RLS 强制执行。

## 3. 信息架构

1. **登录 / 恢复密码**：邮箱和密码登录、发送恢复邮件、设置新密码、登录错误与会话状态提示。
2. **今日工作台**：今日活动时长、已完成任务、连续学习天数、分类时长、今日待办、快速建任务、快速记学习、最近记录。
3. **任务管理**：列表与看板；任务状态 `todo / doing / done / canceled`，优先级 `low / medium / high`，分类 Java / AI / 科研 / 其他，计划日、截止日、项目和里程碑关联；搜索、筛选、排序；过期高亮；删除确认。状态变化不自动改日期或时长。
4. **学习日志**：按用户时区日期浏览；每日多条活动；分类、标题/内容、非负分钟数、Markdown 笔记、可选项目关联；支持历史补录、编辑、删除和确认。每日收获、困难、明日计划保存在独立每日复盘中。
5. **项目中心**：创建学习或科研项目，维护说明、状态、目标、外链与里程碑；显示从关联任务得出的进度；关联任务和活动；支持归档与取消归档。
6. **数据统计**：真实记录热力图、7/30/90 日趋势、分类时长比例、每周总时长、任务完成情况、连续记录天数、周目标达成。空数据时给出引导，不绘制伪造数值。
7. **每周复盘**：自然周从周一开始，自动汇总当周活动与完成任务；编辑本周成果、问题和下周目标；可查看和修改历史周报。
8. **个人设置**：显示账户邮箱与可编辑显示名称；默认时区 `Asia/Shanghai`；可设置每周分钟目标和浅色/深色主题；导出 JSON / CSV；退出登录。

## 4. 核心业务规则

- 每条 `activity_logs` 记录有独立分钟数；学习总时长只由活动记录求和。
- 时长不得为负数。主表单要求正整数，数据库约束接受 `>= 0`，以保持可重建导入记录的兼容性。
- 任务状态变化不添加活动记录、不自动累计时长、不改计划日期或截止日期。
- 允许按过去的日期补录活动；未完成任务不会被定时或日期逻辑自动标记完成。
- 用户选择的业务日期作为 PostgreSQL `date` 保存；`created_at / updated_at` 使用 `timestamptz`。统计按照设置的 IANA 时区确定今天和自然周。
- 连续学习天数按存在至少一条正分钟活动的连续本地日期计算；今天尚未记录时，从昨天向前计算。
- 周从星期一开始；周目标以该自然周正分钟活动总数与 `weekly_goal_minutes` 比较。
- 所有写入失败明确反馈；保存按钮在请求中禁用，防止双击重复创建。删除重要记录需确认。
- 任务与关联对象始终属于同一 `user_id`；删除项目默认受关联限制，用户先处理关联任务/活动/里程碑或显式选择解绑。
- 不使用示例/随机/硬编码记录填充正式统计。

## 5. 响应式与无障碍要求

- 桌面：固定侧栏、顶栏、内容区网格；任务详情可使用详情页或抽屉。
- 手机：精简顶栏、五项底部导航（工作台、任务、日志、项目、统计），单列内容；快速记录触手可及；设置通过顶栏个人入口进入。保留底部安全区并避免虚拟键盘遮挡表单操作。
- 控件可键盘操作，焦点可见，图表提供文字摘要；尊重 `prefers-reduced-motion`。
- Loading、Empty、Error、Success 都必须是可读且有下一步动作的界面状态。

## 6. 不在本版本范围

公开注册、多用户协作、团队权限、第三方论文抓取、AI 自动生成学习计划、后台自动改写任务状态、离线冲突合并和实时多人同步。

## 7. 外部配置依赖

用户需创建 Supabase 项目、运行迁移、在 Auth 中禁用新用户自助注册并创建个人账户、配置站点及本地恢复回调 URL、把 Supabase URL 与 Publishable Key 配入 GitHub Actions Variables。上述步骤完成前，站点显示配置提示，云端功能不冒充已连接。

## 8. 验收矩阵

| 范围 | 验收证据 |
| --- | --- |
| 构建与类型 | `npm run typecheck`、`npm run build` |
| 表单及统计规则 | Vitest 覆盖日期、时长、周界限、连续天数、导出 |
| 关键交互 | Playwright 覆盖未配置态、认证门禁、空状态、响应式导航与表单错误 |
| 云端保护 | SQL 单元/本地 Supabase 验证匿名拒绝、本人读写、跨用户隔离；没有 Dashboard 凭据时报告为待手工验证 |
| Pages | Actions 工作流使用 `npm ci` 构建 artifact；部署结果以 GitHub Actions 实际状态为准 |
